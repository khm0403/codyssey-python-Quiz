# 나만의 퀴즈 게임 — 한국사 편

터미널에서 동작하는 한국사 4지선다 퀴즈 게임입니다.
Python 기본 문법과 클래스(객체 지향), JSON 파일 입출력만으로 만들었으며
외부 라이브러리를 사용하지 않습니다.

프로그램을 종료했다 다시 실행해도 **직접 추가한 퀴즈와 최고 점수가 그대로 유지**됩니다.

---

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로그램 | 터미널 기반 4지선다 퀴즈 게임 |
| 언어 | Python 3.10 이상 |
| 외부 라이브러리 | 없음 (표준 라이브러리 `json`만 사용) |
| 데이터 저장 | 프로젝트 루트의 `state.json` (UTF-8) |
| 기본 문제 수 | 한국사 6문제 (실행 중 추가 가능) |

메뉴에서 번호를 골라 **퀴즈 풀기 / 퀴즈 추가 / 퀴즈 목록 / 점수 확인 / 종료** 를 수행합니다.
퀴즈를 풀면 점수가 계산되고, 기존 최고 점수보다 높으면 갱신되어 파일에 저장됩니다.

---

## 2. 퀴즈 주제와 선정 이유

**주제: 한국사**

- **정답이 명확합니다.** 4지선다 퀴즈는 답이 하나로 딱 떨어져야 하는데, 역사적 사실은
  해석의 여지 없이 정답을 정할 수 있어 채점 로직을 검증하기 좋았습니다.
- **직접 풀면서 개발할 수 있습니다.** 내가 아는 주제라 실행할 때마다 실제로 문제를 풀며
  정답/오답 처리와 점수 계산이 맞는지 눈으로 바로 확인할 수 있었습니다.

---

## 3. 실행 방법

Python 3.10 이상이 필요합니다.

```bash
python3 --version      # 3.10 이상인지 확인
python3 main.py
```

실행하면 메뉴가 뜹니다. 번호(1~5)를 입력해 기능을 선택하고, `5`를 누르면 저장 후 종료됩니다.
`Ctrl+C`나 `Ctrl+D`로 강제 종료해도 오류 없이 저장 후 안전하게 종료됩니다.

첫 실행 때는 `state.json`이 없으므로 **기본 퀴즈 6문제**로 시작합니다.
이후 **퀴즈를 추가하거나 한 판 풀면 그 즉시** `state.json`이 만들어지고,
종료할 때도 현재 상태를 저장합니다.

## 4. 기능 목록

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | 퀴즈 풀기 | 등록된 모든 퀴즈를 순서대로 출제하고, 정답/오답을 즉시 알려준 뒤 최종 점수를 계산합니다. 최고 점수보다 높으면 갱신하고 저장합니다. **등록된 퀴즈가 없으면** 안내 메시지를 출력하고 메뉴로 돌아갑니다. |
| 2 | 퀴즈 추가 | 문제, 선택지 4개, 정답 번호를 입력받아 새 퀴즈를 등록하고 파일에 저장합니다. |
| 3 | 퀴즈 목록 | 등록된 퀴즈의 문제 문장을 번호와 함께 보여줍니다. (정답은 표시하지 않음) **등록된 퀴즈가 없으면** 안내 메시지를 출력합니다. |
| 4 | 점수 확인 | 최고 점수를 보여줍니다. **아직 푼 기록이 없으면** 안내 메시지를 출력합니다. |
| 5 | 종료 | 현재 상태를 저장하고 프로그램을 끝냅니다. |

### 입력 및 예외 처리

숫자를 입력받는 모든 곳에서 아래를 처리합니다. (`ask_number()` 함수가 전담)

- 입력 앞뒤 공백 제거 후 처리 (`" 1 "` → `1`)
- 숫자로 변환할 수 없는 입력(`abc`) → 안내 후 재입력
- 허용 범위 밖 숫자(메뉴 `9`, 정답 `0`) → 안내 후 재입력
- 빈 입력(그냥 Enter) → 안내 후 재입력

문제·선택지 같은 글자 입력은 `ask_text()` 함수가 빈 입력을 걸러냅니다.

그 밖의 예외 상황:

- `Ctrl+C`(KeyboardInterrupt) / `Ctrl+D`(EOFError) → 안내 후 저장하고 정상 종료
- `state.json`이 없음 → 기본 퀴즈 6문제로 시작
- `state.json`이 손상됨 → 안내 메시지 출력 후 기본 퀴즈로 복구

### `main.py` 내부 구조

역할별로 클래스 2개와 공용 함수로 나누었습니다.

| 구성 요소 | 역할 |
|---|---|
| `STATE_FILE` / `CHOICE_COUNT` | 데이터 파일 이름과 선택지 개수를 담은 상수 |
| `ask_number(prompt, low, high)` | 범위 안의 정수를 받을 때까지 반복 질문 (공용 입력 처리) |
| `ask_text(prompt)` | 비어 있지 않은 문자열을 받을 때까지 반복 질문 |
| **`class Quiz`** | **퀴즈 한 문제를 표현** |
| ├ `__init__` | 속성 초기화: `question`, `choices`(4개), `answer`(1~4) |
| ├ `show(number)` | 문제와 선택지 출력 |
| ├ `is_correct(user_answer)` | 정답 여부 판정 |
| └ `to_dict()` | JSON 저장용 딕셔너리로 변환 |
| `quiz_from_dict(data)` | 딕셔너리를 `Quiz` 객체로 복원 (형식 검증 포함) |
| `default_quizzes()` | 기본 한국사 퀴즈 6문제 생성 |
| **`class QuizGame`** | **게임 전체 관리** |
| ├ `__init__` | 속성 초기화: `quizzes`(퀴즈 목록), `best_score`(최고 점수) |
| ├ `load()` / `save()` | `state.json` 불러오기 / 저장 |
| ├ `show_menu()` | 메뉴 화면 출력 |
| ├ `play()` | 퀴즈 출제·채점·최고 점수 갱신 |
| ├ `add_quiz()` | 퀴즈 등록 |
| ├ `show_list()` | 퀴즈 목록 출력 |
| ├ `show_score()` | 최고 점수 출력 |
| └ `run()` | 메뉴 반복 및 기능 호출 |
| `main()` | 프로그램 시작점, 강제 종료 처리 |

## 6. 데이터 파일 설명 (`state.json`)

| 항목 | 내용 |
|---|---|
| 경로 | 프로젝트 루트 `./state.json` |
| 인코딩 | UTF-8 (`ensure_ascii=False`로 한글을 그대로 저장) |
| 생성 시점 | 프로그램이 저장할 때 자동 생성 (첫 실행 시에는 없음) |
| 역할 | 등록된 퀴즈 목록과 최고 점수를 보관해 재실행 시에도 유지 |

### 필드 구조

| 키 | 타입 | 설명 |
|---|---|---|
| `quizzes` | 배열 | 퀴즈 객체들의 목록 |
| `quizzes[].question` | 문자열 | 문제 문장 |
| `quizzes[].choices` | 문자열 배열 | 선택지 4개 (개수는 `CHOICE_COUNT` 상수로 관리하며, 불러올 때 개수를 검증) |
| `quizzes[].answer` | 정수 | 정답 번호 `1`~`4` |
| `best_score` | 정수 또는 `null` | 최고 점수(0~100). 아직 푼 기록이 없으면 `null` |

### 예시

```json
{
  "quizzes": [
    {
      "question": "조선의 4대 왕으로 훈민정음을 창제한 인물은?",
      "choices": ["태조", "정조", "세종대왕", "영조"],
      "answer": 3
    }
  ],
  "best_score": 83
}
```

### 파일이 없거나 손상된 경우

| 상황 | 동작 |
|---|---|
| 파일 없음 (첫 실행) | 안내 후 기본 퀴즈 6문제로 시작 |
| JSON 문법이 깨짐 | 안내 후 기본 퀴즈로 복구 |
| 필드 누락, 선택지 개수 이상, 정답 번호 범위 밖 | 안내 후 기본 퀴즈로 복구 |
| 저장 중 오류 (권한/디스크) | 저장 실패를 알리고 프로그램은 계속 동작 |

`state.json`은 실행 중 생성되는 데이터 파일이라 `.gitignore`로 Git 추적에서 제외했습니다.
저장소를 새로 내려받아 실행하면 기본 퀴즈 6문제로 시작합니다.

## 9. Git 작업 기록

### 커밋 단위와 메시지 규칙

기능 하나를 완성해 동작을 확인한 뒤 커밋하는 방식으로 진행했습니다.
커밋 메시지는 `접두사: 변경 요약` 형식으로 통일했습니다.

| 접두사 | 의미 | 예시 |
|---|---|---|
| `Feat` | 새 기능 추가 | `Feat: 퀴즈 풀기 및 채점 기능 구현` |
| `Fix` | 문제 수정 | `Fix: 강제 종료 시 데이터 유실 방지` |
| `Refactor` | 동작은 그대로, 구조만 개선 | `Refactor: QuizGame 클래스로 게임 로직 분리` |
| `Docs` | 문서 작업 | `Docs: README 실행 방법 및 파일 구조 작성` |

### 브랜치 작업

퀴즈 풀기 기능은 여러 부분(출제·채점·점수 계산)이 얽혀 있어 만드는 도중
프로그램이 동작하지 않는 시간이 생깁니다. `main`을 항상 실행 가능한 상태로
유지하기 위해 별도 브랜치에서 작업한 뒤 병합했습니다.

```bash
git checkout -b feature/play        # 브랜치 생성 및 이동
# ... 기능 구현 및 커밋 ...
git checkout main
git merge --no-ff feature/play      # 병합 (이력 보존)
```

`--no-ff` 옵션을 사용해 병합 커밋을 남겼습니다. 옵션 없이 병합하면
fast-forward로 처리되어 브랜치를 나눠 작업한 기록이 그래프에서 사라집니다.

### clone / pull 실습

원격 저장소를 별도 폴더로 복제해, 다른 환경에서 작업한 내용을
가져오는 과정을 실습했습니다.

```bash
# ① 원격 저장소를 별도 폴더로 복제
git clone https://github.com/khm0403/codyssey-python-Quiz.git quiz-clone

# ② 복제한 폴더에서 README를 수정하고 원격에 반영
cd quiz-clone
git add . && git commit -m "Docs: clone 실습 - README에 한 줄 추가"
git push

# ③ 원래 작업 폴더에서 변경사항 가져오기
cd ../"python Quiz"
git pull
```

`pull` 결과는 `Updating ad0316e..f4e1381 / Fast-forward`로 정상 반영되었고,
해당 커밋(`Docs: clone 실습 - README에 한 줄 추가`)이 이력에 포함되어 있습니다.
`git reflog`에서도 `pull: Fast-forward` 기록을 확인할 수 있습니다.
